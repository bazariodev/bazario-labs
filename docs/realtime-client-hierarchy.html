Realtime client hierarchy

A small transport abstraction sits below RealtimeClient. Each layer owns one kind of decision, so platform mechanics, connection lifecycle, RPC, and domain delivery do not overlap.

  • Transport ADR
  • Idle Watchdog ADR
  • Keepalive ADR
  • Realtime ADR
  • Roadmap

Ownership rule: transport owns one physical attempt; watchdog owns timer mechanics; keepalive owns ping/pong state; realtime owns traffic resets, transport effects, and the logical connection across attempts; higher layers own delivery semantics.

Owns one re-armable inactivity timer; it does not classify traffic.
@bazariodev/keepalive
Owns one configurable idle or immediate ping/pong round and its response deadline; it never touches the transport.
fsm-react / fsm-inspect
Observe the realtime snapshot; they do not control transport resources.

Concern ownership

Every concern has one policy owner. Lower layers report facts; higher layers decide meaning.

Concern Owner Boundary
One connection attempt Concrete transport adapter Maps platform open/message/error/close and releases platform resources.
Transport contract @bazariodev/transport Defines ordered messages and local send admission; contains no policy runtime.
Logical connection lifecycle RealtimeClient Owns intent, attempts, connect timeout, backoff, replacement, and readiness.
Idle timer mechanics IdleWatchdog Arms, resets on command, and emits one idle event without resource policy.
Ping/pong conversation Keepalive Creates idle or immediate probes, bounds each pong response, and emits send or timeout requests.
Traffic reset and liveness effects RealtimeClient Classifies accepted traffic, resets the watchdog, writes probes, and retires attempts.
Realtime wire protocol RealtimeClient Defines connect/ready and ping/pong shapes, validates, and delegates probe state.
Credentials and refresh auth-session Realtime requests fresh credentials but never stores or refreshes them.
Network and wake detection net-monitor Reports environmental change and calls the public reconnect seam.
Request/response delivery rpc Owns correlation, acknowledgement, timeout, and retry eligibility.
Durable delivery and recovery Domain package Owns outbox, idempotency, deduplication, cursors, and state resynchronization.

Dependency rules

  • Transport stays policy-free No FSM, reconnect, heartbeat, auth, network monitor, or cross-attempt queue.
  • Realtime stays adapter-free It consumes the transport contract; the application constructs the concrete adapter.
  • Liveness helpers stay resource-free They emit events; only RealtimeClient resets activity or acts on a transport.
  • RPC stays lifecycle-free It consumes readiness and messages without opening or replacing transports.
  • Domains own replay meaning No lower layer blindly replays application messages after reconnect.

The intentionally small transport seam

A transport is constructed for one attempt, started once, and discarded when that attempt ends. Sending returns normally on local acceptance and throws on rejection; successful return is not a delivery acknowledgement. 

interface Transport {
  start(handlers: TransportHandlers): void;
  send(message: string | Uint8Array): void;
  close(): void;
  [Symbol.dispose](): void;
}

type TransportFactory = () => Transport;

What changed from the earlier draft

Kept: transport abstraction

RealtimeClient uses a reusable one-attempt port. One transport package contains the contract, WebSocketAdapter, HttpAdapter, and WebTransportAdapter.

Removed: ManagedConnection

Transport no longer owns reconnect, heartbeat, offline policy, an FSM, or a cross-attempt queue. Those concerns either belong to RealtimeClient or to a higher delivery layer.

Kept: one lifecycle owner

RealtimeClient alone replaces stale attempts, applies backoff, gates readiness, and turns liveness events into generation-guarded transport actions.

Added: bounded liveness primitives

IdleWatchdog owns one inactivity timer; Keepalive owns one protocol round and response deadline at a time. Neither owns traffic classification, socket writes, closing, or reconnecting. Keepalive can also probe immediately without scheduling through the watchdog.

Implemented: stream adapters

HTTP uses streaming GET and sequential POSTs; WebTransport uses one reliable bidirectional stream. Both preserve text and binary messages with length-prefixed frames. Polling and live upgrades remain out of scope.
