Realtime client hierarchy

One client owns connection intent and attempt replacement. Messages stay opaque. Applications choose the transport and any codec.

The root createRealtimeClient(options) selects the default FSM, event publisher, and retry driver. new RealtimeClient(deps) accepts injected dependencies. The @bazariodev/realtime/core entry has no imports from the default implementation packages. See the current composition decision.

Ownership rule: a transport adapter owns one physical attempt. RealtimeClient owns readiness and recovery. Keepalive owns one abortable probe when configured. RPC owns request matching. The application owns auth, online state, wake handling, and domain recovery.

Module and runtime hierarchy

The lifecycle, event publisher, and retry driver live for one client. Each attempt gets one connection. A monitor exists only when selected.

Default assembly and omission rules

  • createRealtimeClient({ createTransport })Uses the root FSM, event publisher, and retry driver. It creates no Keepalive unless a probe or monitor factory is supplied.
  • createKeepalive: nullOmits monitoring and its probe. Server-specific reply behavior belongs to the application transport or probe integration, with or without a monitor.
  • retry: nullA failed attempt returns to idle. The application may call connect() again.
  • Message admissionOnly ready accepts a send. A true result means local admission, not delivery.

Factories run without a receiver. A connection factory must wait for start() before calling handlers; start() may call them synchronously. Retry callbacks are asynchronous and stale callbacks are ignored.

Dependency rules

  • Transport stays policy-freeNo FSM, retry, liveness, auth, or cross-attempt queue.
  • Adapters stay application-selectedRealtime does not declare transport as a peer dependency. Install the adapter you use.
  • The root and core have different importsThe root factory imports coordination, FSM, and optional Keepalive. The core entry does not import these default implementations.
  • RPC stays lifecycle-freeIt subscribes to the client; it does not open or replace transports.
  • Messages are not replayedThe application decides what work is safe to repeat and when to resynchronize.

Why the earlier layers were removed

No packet channel

A parser and packet classifier made one backend envelope part of the logical client. Use opaque messages and select a codec only when needed.

No retry lifecycle bridge

The retry driver schedules and cancels. RealtimeClient alone sends lifecycle events and checks attempt identity.

No built-in ping or pong

Keepalive accepts a correlated abortable probe. Server-specific reply behavior belongs to the application transport or probe integration.

Safety remains in the owners

Attempt identity, newest-command checks, terminal stop, ready-only sends, and full cleanup protect reentrant and late callbacks.

Transport seam

Each transport is started once for one attempt. It sends and receives its declared message type. Disposal ends that attempt. A successful send means local admission only.

interface Transport<Message> {
  start(handlers: TransportHandlers<Message>): void;
  send(message: Message): void;
  [Symbol.dispose](): void;
}

type TransportFactory<Message> = () => Transport<Message>;
