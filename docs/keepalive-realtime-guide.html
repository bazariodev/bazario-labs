01

One connection owner.
Three focused building blocks.

RealtimeClient owns the logical connection across attempts. Every ready attempt gets an internal protocol handler. Keepalive is enabled by default with two watchdogs; disabling client probes leaves server-ping replies active.

Auth-session → credentials

Supplies fresh auth for each connect handshake. It does not replace the transport.

Net-monitor → recovery intent

Requests an immediate probe after wake, or a reconnect when the network generation changes.

FSM + delays → lifecycle

Drive the planned client's four states, handshake timeout, and reconnect delay. Keepalive uses its own watchdogs.

02

Open first. Ready after handshake.

These are the proposed RealtimeClient states. Transport opening alone does not enable application sends or start keepalive.

Retryable failure → backoff → connecting. RealtimeClient disposes the old attempt and creates a fresh transport. A new protocol handler and, unless disabled, Keepalive are created only after the next valid ready packet.

Entering ready

  1. Transport opensClient writes {type: 'connect', protocol: 1, auth}. Auth is resolved for this attempt.
  2. Server accepts the protocolA valid {type: 'ready', protocol: 1, connectionId} completes the handshake.
  3. Attach attempt servicesCreate the internal protocol handler before notifying ready listeners. Unless keepalive: false, bind its default probe or a custom one, create Keepalive, subscribe, and start. Reset the retry counter.

Leaving an attempt

  1. Invalidate its generationOld callbacks lose permission to act on the current connection.
  2. Stop keepalive before the transportAbort the pending probe and dispose both watchdogs, dispose the protocol handler, then close and dispose the old transport.
  3. Apply the client's connection intentRetryable failure enters backoff. Manual disconnect clears intent and returns to idle.

Two lifetimes, two state machines. RealtimeClient survives many attempts. Keepalive goes from inactive → monitoring idle ⇄ awaiting promise → terminal. It never restarts after failure or stop().

    04

    Packets and failures take different paths.

    Incoming: transport → client → protocol handler

    1. Guard and validate the envelopeIgnore an old generation. Size-check, decode JSON, validate the envelope and its legality in the current state.
    2. Report inbound activityIn ready, validated incoming packets call activity(). Outgoing writes never do.
    3. Consume controls firstThe internal handler consumes every ping/pong and answers server pings, even with disabled or custom client probing. Only message.data reaches application listeners.
    4. Fulfill after validationA validated response fulfills the probe promise. Keepalive cancels its deadline and resumes idle monitoring through the promise reaction.

    Outgoing: probe → handler → guarded writer → transport

    1. Arm before invokingKeepalive stores a fresh pending operation, suspends idle monitoring, arms the deadline, and calls probe(signal).
    2. Register, then sendThe handler sets up matching and abort cleanup before sending on the current connection. It uses this signal instead of a second deadline.
    3. Reject failed admissionThe internal control writer is bound to this ready attempt and throws if it cannot send. The handler rejects the probe promise. Custom probes must likewise reject failed admission.
    4. Wait for the correct proofA local write or a response over another connection cannot fulfill this check. No retry or replay across attempts.
    Failure routing in the proposed client
    EventKeepaliveRealtimeClient
    Probe deadline expiresAbort; terminal {type: 'timeout'}Retire the current attempt; backoff while intent remains true

    One failure, one recovery decision. Keepalive is already terminal before onFail runs. Even if a failure subscriber awaits, no new probe is scheduled. A later close callback from the retired transport must not schedule a second reconnect.

    05

    The parent wiring.

    Illustrative integration code for the future RealtimeClient. These snippets use the implemented Keepalive API; the request handler, client helpers, handshake, and FSM transitions are illustrative and not implemented here.

    1. On ready: create, subscribe, start

    The internal handler is always created for this ready attempt. Omitted options use its probe; false skips only Keepalive. The future client validates durations and custom-probe callability at construction, using the validation approach in its ADR. A custom probe must await and validate its response, honor abort, and avoid its own deadline or retries. RealtimeClient does not import RPC.

    // Private helper names are illustrative; realtime is not implemented yet.
function isCurrentReady(attempt) {
  return currentAttempt === attempt && state === 'ready';
}

function attachReadyServices(attempt, options = {}) {
  const handler = new RealtimeProtocolHandler({
    send: (packet) => writeControl(attempt, packet),
  });
  attempt.protocolHandler = handler;
  if (options === false) return; // Server pings still receive replies.

  const {
    idleMs = 30_000,
    deadlineMs = 30_000,
    probe = (signal) => handler.probe(signal),
  } = options;
  const keepalive = new Keepalive({
    idleMs,
    deadlineMs,
    logger, // Forward the client's configured diagnostics.
    probe(signal) {
      if (!isCurrentReady(attempt)) throw new Error('Attempt retired');
      return probe(signal);
    },
  });
  attempt.keepalive = keepalive;
  keepalive.onFail((failure) => {
    if (!isCurrentReady(attempt)) return;
    retireAttempt(attempt, { kind: 'keepalive', cause: failure });
  });
  keepalive.start();
}
    2. In ready: report inbound activity and route payloads

    encodeAndCheckSize performs JSON encoding and the configured byte limit. receiveValidated runs after packet and state validation. The internal handler returns true for every ping/pong, including unmatched pongs. It has no timers or reconnect policy. A peer-reply write failure reaches the client directly; a local probe write failure rejects its promise. Listener helpers isolate subscriber exceptions.

    function receiveValidated(attempt, packet) {
  if (!isCurrentReady(attempt)) return;
  attempt.keepalive?.activity();
  try {
    if (attempt.protocolHandler.receive(packet)) return;
  } catch (error) {
    retireAttempt(attempt, { kind: 'send', cause: error });
    return;
  }
  if (!isCurrentReady(attempt)) return;
  if (packet.type === 'message') emitMessage(packet.data);
}

function writeControl(attempt, packet) {
  if (!isCurrentReady(attempt)) throw new Error('Attempt retired');
  attempt.transport.send(encodeAndCheckSize(packet));
  // Outgoing admission is not evidence of peer liveness.
}

function sendApplication(attempt, data) {
  if (!isCurrentReady(attempt)) return false;
  try {
    attempt.transport.send(
      encodeAndCheckSize({ type: 'message', data }),
    );
  } catch (error) {
    reportSendError(error);
    return false;
  }
  return true; // The write was admitted, even if the attempt retired during send.
}

function probeNow() {
  if (state === 'ready') currentAttempt?.keepalive?.probeNow();
}
    3. On retirement: invalidate, stop, dispose, decide

    The same generation check must guard every transport callback. Manual disconnect clears wantsConnection before retirement; a non-retryable protocol failure does too. This example shows ordering, not the full disposal/error-notification implementation.

    function retireAttempt(attempt, error) {
  if (currentAttempt !== attempt) return; // Already retired.
  generation += 1;
  currentAttempt = null; // Invalidate before any cleanup callbacks.

  attempt.keepalive?.stop(); // Aborts the local probe, if present.
  attempt.protocolHandler?.stop(); // Ends this attempt's handler lifetime.
  attempt.transport.close();
  attempt.transport[Symbol.dispose]();

  if (error) reportError(error);
  if (wantsConnection) enterBackoff();
  else enterIdle();
}

// Backoff expiry creates a NEW transport and begins a NEW handshake.
// Its valid ready packet creates a NEW handler and optional keepalive.

    For the complete API and lifecycle rules, see the canonical Keepalive contract and package usage example.

    06

    What the timing actually guarantees.

    idleMs + deadlineMs

    A quiet, unanswered connection

    Expected detection time from the last validated incoming packet, plus scheduling delay. With the illustration's 30 s + 5 s, failure occurs around 35 s. An immediate probe skips the idle wait.

    1 … 2,147,483,647 ms

    Allowed duration range

    Both values must be integer milliseconds. Each watchdog validates its duration. Invalid values throw RangeError; no clamping or rounding. These are technical bounds, not recommended production settings.

    Outgoing writes cannot hide a dead peer

    Only validated incoming packets refresh idleness. A client sending presence or telemetry without receiving anything still probes after the idle window. Local buffering never counts as proof of peer reachability.

    Background time is approximate

    Event-loop work, background throttling, and sleep can delay callbacks. Net-monitor should request a ready-state probe after wake; a confirmed network change may request immediate replacement instead.

    A response window is independent

    While a promise is pending, activity cannot extend its deadline. Only fulfillment resumes idle monitoring. The consumer decides which response is valid.

    Reconnection does not restore messages

    Realtime has no application replay queue. A successful send means local admission. RPC may own acknowledgements and safe retries; domain modules must resynchronize missed state after onReady.

    The detailed rules have one home. See the Keepalive contract for scheduler obligations, callback errors, and complete failure delivery, and its cancellation rules for probe cleanup. Handshake timeout and reconnect backoff belong to RealtimeClient.
