Architecture guide / realtime connections

One attempt
at a time.

RealtimeClient owns connection intent and recovery. Keepalive runs an application-supplied probe. The transport carries opaque values.

The root package assembles default lifecycle, events, retry, and transport dependencies. The /core entry accepts dependencies and imports no default implementations. JSON encoding is opt-in. Neither package defines a reserved handshake, ready, message, or ping packet. Read the current composition record and the Realtime README.

Separate decisions
from transport work.

Each layer has one job. The client retires an attempt before it releases that attempt's resources.

02

The client has five states.

Only ready admits local sends or probeNow(). Retry is asynchronous, even at zero delay. Stop is terminal.

Recoverable failure

The client retires the attempt, aborts its monitor, and disposes its transport. A current retry may create a new attempt. Without retry, the client returns to idle.

Newest effective command wins

Reconnect, disconnect, or stop during cleanup replaces the older operation. An inert connect does not supersede it. Late events from the old attempt are ignored.

Stable snapshots

Subscribers receive a snapshot for each committed state. Treat snapshot and context values as read-only. A nested command suppresses obsolete remaining delivery.

    04

    Select a wire format.

    A raw adapter passes values unchanged. Wrap it in JsonTransport only when the peer uses JSON text frames.

    JSON transport, explicit

    const client = createRealtimeClient({
  createTransport: () => new JsonTransport(
    new WebSocketAdapter({ url }),
  ),
});
client.onReady(({ reason }) => {
  // Open transport, not server authentication.
});
client.connect();

    The helper serializes once, parses once, and skips malformed or non-text input. It does not validate an application schema.

    Correlated probe through RPC

    let rpc;
const client = createRealtimeClient({
  createTransport,
  keepalive: {
    idleMs: 30_000,
    deadlineMs: 5_000,
    probe: (signal) =>
      rpc.probe({ method: 'ping' }, { signal }),
  },
});
rpc = new RpcClient({ channel: client });
client.connect();

    Create RPC before connecting. A matched server error proves a round trip, not authentication or application success. The probe controls correlation.

    The injected core requires application-supplied fsm, events, and createTransport. retry and createKeepalive are optional. A selected monitor factory gets an attempt-bound send and message port.

    05

    Three waits, three owners.

    Connect deadline

    Bounds the wait for the transport's open callback. It does not prove server readiness.

    Probe deadline

    Bounds one monitor probe. Keepalive aborts its signal at the deadline and ignores stale completion.

    RPC response deadline

    Bounds one request. RPC owns response matching and does not replay requests after recovery.

    Incoming messages reach the client once. A monitor may observe activity, but unrelated messages do not satisfy a correlated probe. The application owns login, online intent, wake policy, and server synchronization.

    Server-specific replies belong to the application's transport or probe integration, whether a monitor is selected or not. Set retry: null to return to idle after a connection failure and reconnect manually.
